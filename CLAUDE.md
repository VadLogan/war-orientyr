# WAR·Орієнтир — «Щоденний дайджест війни» (Next.js)

Daily war digest (UA/EN/DE/FR), ported from a single-file Artifact to Next.js. See README.md (Ukrainian) for the remaining plan.

## Commands
- `npm run dev` — localhost:3000
- `npm run publish -- <new-digest.json> [--force]` — new issue: copies the current `public/digest.json` to `issues/<date>.json`, installs the new file as `digest.json`, adds its date to `issues/index.json`. Same date = correction (no archiving); older date refused. Either way, a `losses.series` day the new file has emptier (ru/ua, e.g. hand-backfilled russian MoD claims) keeps the current values.
- `npm run validate` — parses all `public/` JSON, checks digest.json schema keys, that `issues/index.json` contains digest's date, and that every strike in digest.json's `deepstrikes` section is in `strikes.json` (by `id` or `item`; notes without emoji / ℹ️ and `geo: null` items exempt). Run after any data change; `prebuild` runs it too, so Vercel won't deploy a stale strikes map.
- `npm run build` — no test suite; validate + build is the check.
- `npx tsx scripts/stats.ts [date] [--month]` — numbers for the main editor: the day against yesterday, 7/30-day averages and “most since” for every timeline / losses / strikes series; on the 1st (or `--month`) last month against every earlier month. Self-check: `--test`.

## Architecture
- Routes (all statically generated, `dynamicParams = false`): `/[date]`, `/dashboard/[date]`, `/maps/[date]`, `/strikes/[date]`, `/en/…`, `/de/…`, `/fr/…` the same; no date = latest issue. Files: `app/(uk)/…`, `app/(en)/en/…`, `app/(de)/de/…`, `app/(fr)/fr/…` — route groups, each with its own root layout so `<html lang>` is static.
- German: a `/de` page with German text (digest: every string of the issue in `i18n/de.json`; article: `*.de.json`) renders in German; otherwise it renders the English page (`DigestPage`/`ArticlePage` call themselves with `lang="en" from="de"`) with the notice `DE_MISSING` (`lib/ui.ts`, shown by `Shell`), canonical = the `/en` URL and no `de` hreflang. The dashboard, maps and strikes pages exist in all three languages (`/de/dashboard`, `/de/maps`, `/de/strikes`): a German issue falls back to its English text, then Ukrainian (`readIssue` in `lib/data.ts`; the dashboard shows `langNoteEn`/`langNote`), and each fetched data file falls back from `public/i18n/de/` to `public/i18n/en/` (`useJson`). German UI strings: `UI.de` (only `brand` and a few `art` keys inherit English; `stk`/`evLg` are replaced whole, so new keys there need a German value); inline panel texts use a three-way `tr(uk, en, de)`; map labels `DIRS` (`mapParts.tsx`) and `STK_CITIES` (`strikeParts.tsx`) carry `uk`/`en`/`de`. `strikes.json` `coverage.de` falls back to `coverage.en`.
- French (`/fr`, since 2026-11-10) works exactly like German, through the same code paths: `SubLang`/`SUBS`/`isSub` and `SUB_MISSING` in `lib/ui.ts` (the fallback notice), `UI.fr`, `i18n/fr.json` (`npm run i18n:missing:fr` / `i18n:merge:fr`), `*.fr.json` article files, `tr(uk, en, de, fr)` in panels, `fr` on `DIRS`/`STK_CITIES`, house style `houseStyle(str, "fr")` (lowercase russie/russe, flags). Until an issue has full French text, `/fr/<date>` shows the English page with the French notice; data files fall back to English. Page files are thin wrappers around `components/DigestPage.tsx` / `components/dash/DashPage.tsx`.
- `proxy.ts` — language choice: a visitor without a `lang` cookie whose Accept-Language doesn’t start with uk/ru is redirected from a Ukrainian page to its `/de` (de), `/fr` (fr) or `/en` (anything else) twin; the language picker (`components/LangLink.tsx`) sets the cookie. `/en/…`, `/de/…` and `/fr/…` are never redirected.
- `lib/data.ts` — server-only data access (reads `public/` at build time, `styleData` applied; source matrix precomputed). `lib/page.ts` — `resolve()`, `dateParams()`, `pageMeta()` (title, hreflang, canonical). `lib/routes.ts` — `href(lang, view, date, latest)`.
- Digest is Server Components only (`components/digest/`, `Mast.tsx`, `Shell.tsx`); client islands: `digest/ChkToggle.tsx`, `IssueSelect.tsx`, `HashRedirect.tsx` (old `#date`/`#dashboard` links → paths). Keep dashboard imports out of digest modules, or the dashboard JS ships on digest pages.
- Dashboard is a client tree: `dash/DashProvider.tsx` (context from `ctx.ts`, router-based navigation, gets trimmed `DashIssue` data from the server), `Panels.tsx`, `Timeline.tsx`, `Losses.tsx`, `LineChart.tsx`, `SourceMatrix.tsx`, `Maps.tsx` (d3-geo/d3-zoom, lazy). `/maps` = `DashPage view="maps"` → `MapsView` (full `MapsCompare`: filter rail — view/pair, claims period, reference source, verdict; verdict bar, claims table; above it three presets `PRESETS` — what changed / russian claims / compare sources, and “the week on the front”: DeepState `dsEvents` in the 7 days to the snapshot + `ds_nc` against the archived snapshot a week earlier; under the map a slider “what each side reported” for the rail's period window and direction — DIVGEN claims (with DeepState/ISW verdicts) and DeepState changes (`dsEvents`, with whether/when russia claimed them), newest first, filter all / russian / DeepState; ▶ (rail and map controls, so also in full screen) plays the archive as a tour — `lineChanges` (`mapParts.tsx`) finds where DeepState's outline vertices differ between snapshots, the map flies to each change (d3 zoom out-across-in), swaps the snapshot there with a cross-fade and captions it (DeepState's note from the newest snapshot's `dsEvents` + a nearby DIVGEN claim, else the nearest town); the caption is the player (‹ ▶/❚❚ › n/N ■ over all stops of the archive; paused, it lists every DeepState note and DIVGEN claim near the place, numbered; each is a numbered point on the map — hover highlights both, a list click flies to the point, a point click scrolls to its item; the general claim/change markers hide during the tour); direction labels and the full-screen claims list hide during the tour; ■ stops it and returns to the issue's snapshot and the whole front; the view lives in the URL hash `#v=ds&p=&n=7&o=&d=pok&s=<date>&c=<claim id>&e=0&a=0`, so links share it; direction sectors and labels use each direction's dashboard colour (`dirOrder`/`dirCol` in `lib/text.ts`; the maps/strikes pages get no timeline, so `DashPage` ships `LATEST.dirOrder`), the picked one solid, others faded, each switchable in the rail (+ hide/show all); the rail starts hidden on phones; on wide screens the rail is sticky and scrolls itself while the map column scrolls with the page; the legend sits under the map (full screen: top bar); direction labels are placed in screen px without overlaps (right/left of the anchor, kept clear of the zoom buttons and the map edges); “the line then and now” (rail, `chg` = off/7/30 days, hash `g`, default 7): DeepState's area against the archived snapshot that many days earlier — taken (red) / retaken (blue) patches drawn as SVG masks of one area by the other, the old line dashed, and a ring per change (`lineDiff` in `mapParts.tsx`: `lineChanges` + who moved, by `inRings`) that flies in on click; under the map “how far the occupied territory is”: every city's straight-line km to DeepState's occupied area now and its change in 7/30 days (`toArea` in `lib/geo.ts`, self-check `npx tsx lib/geo.ts`; the border with russia is not counted), a row or any click on the map (not on a marker or label) drops a pin with a line to the nearest occupied point; area tiles at the bottom). Both full maps (`useZoom`): the wheel zooms only with Ctrl/⌘ or a trackpad pinch (full screen: any wheel), otherwise the page scrolls and `mWheel` flashes over the map; the dashboard shows `MapsTeaser` (still map + numbers, links to /maps). Claim verdict = shape + fill (`Mark`). Both full maps are web-mercator with a plain / terrain / satellite basemap toggle (`BASEMAPS`, `Tiles256` in `Maps.tsx`; land is filled only on "plain"). `/strikes` = `DashPage view="strikes"` → `StrikesView` (`StrikesMap`: filter rail — period, target groups, confirmation, local authorities, search, potential targets; tiles, timeline, map with icon markers grouped per place, full legend, list by day); the server renders `StrikesSeo` (title, totals, 30-day list as HTML) until the client page has its data; the dashboard shows `StrikesCard` (server HTML: totals, type bar, latest strikes; its map is `StrikesThumb`, drawn in the browser with lazily loaded d3). Target groups, colours, icons and the marker: `dash/strikeParts.tsx`. Client JSON fetches must use absolute paths (`/prices.json`). `hooks.ts`: `useSticky`, `useJson`, width hooks.
- `/maps` SEO: share image `app/og/maps/[file]/route.tsx` → `/og/maps/<date>.png` (static, one per issue date, no words so all languages share it; set by `mapsImg` in `lib/page.ts`); a schema.org `Dataset` JSON-LD (`mapsLd` in `DashPage.tsx`); `MapsSeo` (server HTML: areas, the week's DeepState changes, the month's DIVGEN claims, direction links) shown until `MapsCompare` has its data (`onReady`; the map stays mounted but hidden so its width/zoom hooks attach). Direction pages `/maps/<slug>` (+ `/en`, `/de`; slug = `DIRS[].en` lowercased, `mapsParams`/`dirSlug`/`dirHref` in `lib/page.ts`, `resolve()` returns `dir`): the latest issue with that direction preselected (`MapsCompare dir0`, a hash `d=` wins), own title/description/canonical, in the sitemap. The digest's front section ends with the General Staff's directions of the day linking to the map (`DirLinks` in `digest/Digest.tsx`: latest issue → direction page, older → `/maps/<date>#d=<id>`; string `mpOnMap`).
- `/articles` (+ `/en`, `/de`): every article, newest first — `components/ArticlesPage.tsx` (server, `getArticleList` in `lib/data.ts`: topic, format = presentation → interactive / `scenarios` block → scenarios / else analysis, ≈minutes from word count, sources, languages) + client island `ArticleList.tsx` (search over title/lead/kicker, topic and format chips with counts, sort newest/longest, month groups, the newest as a hero when unfiltered; wide screens: sticky bar filtering as you type; phones: one bar opening a full-screen native `<dialog>` whose choices apply on “Show N”, active filters as removable tags). Strings `UI.*.arts`, styles `.al-*`. The Shell's fifth tab “Статті” (view `articles`) is current on the list and on every article page.
- Records of the day: `lib/records.ts` (`dayRecords`) finds, for an issue's date, russian loss categories above every earlier day of that issue's `losses.series` (needs ≥30 earlier days) and a strike (`issue ?? date`) farther from the front (`stkDist`) than every earlier one in `strikes.json`; `getRecords` (`lib/data.ts`) → `Records` in `Mast.tsx` (classes `drec-*`, strings `UI.*.rec`), shown after the issue’s article cards (order under the lede: feature cards, then records, then “new on the site” — `NEW_PAGES` in `Mast.tsx` lists the promoted pages, maps / strikes / articles (the articles card shows the three newest covers), empty = no block) only when there is a record, linking to that day's `/dashboard#losses` or `/strikes`. Self-check: `npx tsx lib/records.ts`.
- `lib/ui.ts` (UI strings), `lib/text.ts` (house style, plural, dates), `lib/icons.ts`, `lib/strikes.ts`; `types/digest.ts`.
- `app/globals.css` — original styles; components keep the original class names. Active links use `aria-current`.

## Data (`public/`)
- Updated daily: `digest.json`, `issues/<YYYY-MM-DD>.json`, `issues/index.json`, `strikes.json`; sometimes `prices.json`, `recruit.json`, `maps/maps.json` + `maps/archive/`.
- Articles: `articles/<YYYY-MM-DD>/<name>/` — `preview.uk.json` (required) / `preview.en.json` = `{title, lead?, button?, url?, image?, imageAlt?}` (+ `topic` in `preview.uk.json` only: a key of `UI.*.arts.topics` — front/ru/usa/arms/world — the filter on `/articles`); `article.uk.json` / `article.en.json` = `{kicker?, title?, lead?, toc?, image?: {src, alt, caption}, blocks, sources?: [{title, url, note}]}`. Blocks (types in `types/digest.ts`, rendered by `Block` in `components/ArticlePage.tsx`): p|h2|h3, list, table (`num` = numeric column), cols, chart (`kind: bar|col`, rows with `value`/`group`/`tone`), stats (strip or `kind: tiles`), estimate (`**bold**`), diverge, vs, links. An `h2` that repeats a digest section title carries `section: <id>` (e.g. «Що кажуть на болотах» → `kremlin`) and shows that section's icon (`secIcon`), in both languages — validate fails without it. `toc: true` = contents rail of the h2s. Image: the one `image` names (convention `cover.<ext>`; an image with text in it gets an English copy `cover.en.<ext>` named by the `.en.json` files), else the first jpg/png/webp/avif/gif. Every folder under an issue's date = a card on that issue right after the headline and lede — always the first block, before the records of the day and the first section (`Mast.tsx`, folder-name order) — so the main page links only articles under the latest issue's date. Card links to `url`, else to `/articles/<date>/<name>` (+ `/en/…`; generated only when `article.uk.json` exists). English files fall back to Ukrainian; i18n scripts skip `articles/`. `<name>` is the URL: a-z, 0-9, -. validate checks it.
- Static: `landcost.json`, `maps/strikes-base.json`, `maps/targets.json`.
- Data vs text: every data file in `public/` is shared by both languages; English is only text. `i18n/en.json` (committed) maps each Ukrainian string to English; `lib/i18n.mjs` (`texts`, `translate`) applies it — used by the script and the app. Digest pages are translated on the server (`lib/data.ts`). For files the dashboard fetches in the browser, `scripts/i18n.mjs build` (run by `predev`/`prebuild`) writes text-only subsets to `public/i18n/en/<file>` (gitignored); `useJson` fetches data + text and combines them. A file that is not fully translated stays Ukrainian (digest pages show the "written in Ukrainian" note). House style for English (lowercase russia, country flags) is applied at render time (`houseStyle(str, "en")` in `lib/text.ts`).
- German: `npm run i18n:missing:de` (the current issue + the dashboard data files — strikes, maps + archive, prices, recruit, targets, landcost; not archived issues → `i18n/missing.de.json`; the count is split into issues / daily data / static data — static = `STATIC` in `scripts/i18n.mjs` plus the UI strings in `lib/ui.ts`, translated once; daily = new strikes and map events) → fill in → `npm run i18n:merge:de` → commit `i18n/de.json`. `scripts/i18n.mjs build` writes `public/i18n/de/` for every fully translated data file (a file not yet fully German is shown in English). House style: lowercase russland/russisch/kreml, flags at render time (`houseStyle(str, "de")`).
- New data → `npm run i18n:missing` (writes `i18n/missing.json` with empty values) → fill in English → `npm run i18n:merge` → commit `i18n/en.json`. Translate raw strings; keep lowercase “russia/russian/kremlin”, British spelling, glossary as in existing entries (Ukraine’s General Staff, Air Force, russia’s MoD, USF, direction names Pokrovsk, Kostiantynivka…).
- Artifact is still the primary publisher; repo copy is synced manually (including `strikes.json` — the map's only source; digest items' `geo` is not read), then validate + commit → Vercel rebuilds (pages are generated at build time, so data changes need a deploy).

## Tools
- Maps (`<MapsCompare />`): `cd ../war-orientyr-scrappers && npm run maps` — scrapes DeepState / DIVGEN / ISW, encodes layers, stages them in `tools/maps/in/` (gitignored), runs `tools/maps/build.py` (shapely/pyproj via `uv run`), cross-source check (`check.ts`: freshness, area jumps, pair disagreements, DIVGEN claims unconfirmed by DS/ISW), then replaces `public/maps/maps.json`, archives it as `public/maps/archive/<date>.json` (+ `archive/index.json`) and runs validate. `<MapsCompare />` on `/dashboard/<date>` loads the newest archived snapshot on or before that date (`getMapsUrl` in `lib/data.ts` → ctx `MAPS`); the strikes map and price-of-a-kilometre panel stay on `maps.json`. Every script is described in `../war-orientyr-scrappers/README.md`. Logs + report: `../war-orientyr-scrappers/logs/<date>.log|.report.json`. maps.json `dsEvents` = DeepState day events (places linked in its update notes, `k` ru/ua/fix, `ru` = the earliest DIVGEN claim naming the place → "when russia said it"; `deepstate/events.ts`), shown on /maps as triangles + their own table; their texts go through i18n like the DIVGEN titles. Commit `public/maps/maps.json` after reviewing the report.

## Conventions
- UI strings live in `UI.uk` / `UI.en` in `lib/ui.ts`. Content is Ukrainian-first.
- Deploy: Vercel (`@vercel/analytics`, `@vercel/speed-insights` in layout).
- Knowledge graph: `graphify-out/` (`.graphifyignore` excludes data JSON). Run `graphify update .` after code changes.
